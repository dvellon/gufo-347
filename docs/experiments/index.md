## How to read a row

| column | meaning |
|---|---|
| # | queue number (with a letter for a re-run or amendment, e.g. `205c`), `sim-NNN` for a CPU simulation, or the packet's short name |
| what was tested | the short title; long descriptions, paths and internal names are cut |
| kind | experiment, cpu-sim, research, engineering or not-run (table above) |
| verdict | the true verdict after the audit (below) |
| detail | the audit's reading in short: the judge's own labels, sub-results, or the cause of an INVALID run |
| key number | the headline effect and its 95 % bootstrap CI where one exists (usually % change in decode tok/s vs the same-run base arm) |
| in production | yes / no / partly / n.a. (n.a. for tools, reports and runs with nothing to adopt) |
| what happened next | promoted in X, rerun as Y, superseded by Z, folded into Z, parked, dropped, or open item |
| date | New York date of the verdict (a `~` date is the ledger position of a row with no date of its own) |

| verdict | meaning |
|---|---|
| **GO** | passed its pre-registered line or gate; a GO is a candidate, not yet production (see "in production") |
| **KILL** | failed its line, including "no gain", quality failures and exactness failures |
| **REVIEW-POWER** | the effect is real or near the line, but the run had too few pairs to call it |
| **REVIEW-HOST** | host interference (foreign CPU / GPU load, paging) stopped a clean call |
| **REVIEW-EXACT** | an exactness check flagged differences that needed classification before a call |
| **REVIEW-OVERRIDE** | a review result that was accepted (and promoted) by an explicit decision |
| **REVIEW-OTHER** | inconclusive for another reason (near-tie, diagnostic with no line, mixed sub-results) |
| **INVALID-harness** | our test tooling failed (judge bug, crashed analysis, miscalibrated control) |
| **INVALID-knob-check** | the arm could not prove its feature was active, or the feature never armed |
| **INVALID-launcher** | the run's launcher failed before the measurement |
| **INVALID-sample-count** | the run compared fewer requests than its rule requires |
| **INVALID-exactness** | an exactness or determinism failure made the speed comparison void |
| **INVALID-setup** | build, host-memory, host-load or engine-crash conditions stopped the run |
| **PARKED** | stopped by decision with a result on record (below a line, or waiting on a dependency) |
| **REPORT** | report-only measurement or analysis with no GO line |
| **DONE** | an engineering change that was completed (fix, tool, amendment, promotion package) |
| **NOT-RUN-superseded / parked / folded / abandoned** | never measured: replaced by a later run, parked by decision, folded into a broader run, or left behind when the chain moved on |
| **PENDING** | still running when the log was generated |

Caveats:

- The ledger was written for the people running the queue, so titles are terse. Where a row and the methods page
  disagree, the methods page is the corrected reading (for example the paging audit).
- Many GO numbers were later **corrected for host paging** (see [Methods: the paging audit]({{ site.baseurl }}/methods/#the-paging-audit)).
  The key number is the one the audit settled on, which is usually the number as first booked.
- One idea can appear on several rows (build, amendment, re-run); exact duplicates were merged.
- A CPU-sim GO means "worth a live test", not a measured gain.
- Numbers from internal workloads (the private agent and chat replays) are shown as numbers only; the workloads are not published.
